# BiliBiliSubtitle

Chrome Manifest V3 插件，为 B 站视频提前生成字幕：**下载完整音轨 → 识别 → 显示原文**。需要译文时再开启翻译。无需构建、本地服务器或 FFmpeg。

## 1.4 新功能

- **语音短段同步（1.4.0，默认）**：保留 Qwen，先按原音频停顿切成最长 6 秒的短段，每段文字固定在对应音频的绝对位置，不再按全文字数均分整条时间轴。播放器显示「语音分段」。这是短段定位，尚不是逐字强制对齐；请求次数和等待时间会增加。
- 旧的硅基官方整段默认配置会一次迁移到「语音短段」，保留密钥及模型；已明确选用的其他档位保留。新模式独立缓存，需要重新生成当前 P。

### 之前的功能

- **默认 Qwen 识别（1.3.3）**：默认模型改为 `Qwen/Qwen3-ASR-1.7B`。更新后，旧的硅基流动官方地址 + 默认 SenseVoice 配置会一次迁移到 Qwen；自定义模型、网关、其他服务和密钥保留。播放器直接标明「估算时间轴」，避免把文字识别完成误当作时间已经对齐。
- **跳转与延迟校准（1.3.2）**：拖动进度条时隐藏旧字幕，跳转结束立即按视频时间定位。延迟按每集自动保存；仅变更时间参数不再重置校准。字幕慢 3 秒时，在「AI 字幕 → ⋯ → 字幕延迟」点「−」调至 `-3.0 s`。
- **字幕背景透明度（1.3.1）**：播放器「AI 字幕 → ⋯」拖动滑块立即预览、松开自动保存，切 P 和刷新后保留；100% 去掉底色，文字保持清晰。设置页「字幕样式」也可调整并保存。
- **识别档位**：可选语音短段、原音轨整段直传、分段识别及兼容识别。无需设置切片时长、并发数或批量上限。
- **自由选择**：在分 P 和合集目录中搜索、复选、全选搜索结果或清空。选择会在本次浏览器会话中保留；单次最多 500 个视频。
- **跟随识别下一 P**：播放当前视频时，在后台准备紧接着的下一 P；不递归处理整个合集。
- **全自动识别**：进入视频页后自动生成字幕，切 P 后继续跟随。自动任务遇到可用原生字幕直接跳过，不调用识别或翻译服务。
- **独立翻译开关**：手动任务和自动任务都遵守它。默认关闭，原文识别完成即可播放或导出，不受翻译等待和失败影响。
- **模型选择**：识别和翻译分别提供下拉列表及「刷新模型」，也可手动填写自定义模型 ID。
- **注册入口**：密钥栏下方提供[硅基流动注册 / 获取密钥](https://cloud.siliconflow.cn/i/cW7ksWMh)，使用作者提供的邀请链接。

全自动和下一 P 跟随开关默认关闭，在弹窗及设置页均可操作并同步。弹窗修改立即生效；设置页修改后点击「保存设置」。关闭自动开关会停止对应的自动任务，手动任务继续执行。

## 安装与更新

**[下载最新安装包](https://github.com/yesifu/BiliBiliSubtitle/releases/latest/download/bili-whole-subtitles.zip)** · [全部版本](https://github.com/yesifu/BiliBiliSubtitle/releases)

2. 开启「开发者模式」，选择「加载已解压的扩展程序」。
3. 选择包含 `manifest.json` 的文件夹。源码目录可直接安装；ZIP 需先解压。
4. 在设置页填写 API Key 并保存，刷新已打开的 B 站视频页。
5. 更新时覆盖原插件目录，在扩展管理页面点击「重新加载」，再刷新视频页。

## 使用

生成范围可选「当前视频」「全部分 P」「整个合集」或「自由选择」。自由选择只处理勾选的视频；默认复用已识别原文和字幕缓存，勾选「忽略缓存」才会重新识别。用户示例 [BV13Q4y1C7hS](https://www.bilibili.com/video/BV13Q4y1C7hS/) 是 200 个分 P，可直接全选或只选需要的章节。

生成时无需播放，可以关闭弹窗，但需保持浏览器运行。任务逐个视频处理，单集失败不影响后续视频。自动任务等待当前手动任务完成后执行；自动预识别始终只跟随下一集。取消任务会清空等待中的自动队列。关闭浏览器或重载扩展会中断当前任务，已完成字幕与识别片段会保留。

播放器中的 AI 字幕按钮可开关字幕、调整延迟、字号和背景透明度。透明度适用于所有视频，默认 24%（保持原有底色），不会重新识别或翻译。支持进度跳转、倍速、网页全屏和播放器全屏。独立画中画窗口不包含此字幕层。弹窗可导出 SRT / VTT。

延迟校准只影响本集在播放器中的显示，刷新、再次打开后保留；其他分 P 独立保存。点「−」提前、点「+」推后，每次 0.5 秒。「恢复显示默认值」清除本集延迟。导出仍使用识别结果的原始时间。固定延迟能校正整体快慢；如果各段偏差不同，仍需要原生字幕或返回逐句时间戳的识别接口，整段按文本估算不能保证语音对齐。

## 模型与接口

| 用途 | 预置 / 默认 |
| --- | --- |
| 识别服务 | 硅基流动，`https://api.siliconflow.cn/v1` |
| 识别模型 | `Qwen/Qwen3-ASR-1.7B`（默认）；保留 SenseVoiceSmall、TeleSpeechASR 预置，可刷新账户可用模型 |
| 翻译模型 | DeepSeek-V4-Flash、DeepSeek-V4、GLM-5.2、Kimi-K2.7-Code，以及原有 Qwen2.5-7B-Instruct |
| 翻译默认 | 原有 `Qwen/Qwen2.5-7B-Instruct`，目标语言简体中文 |

2026-09-07 用户账户模型列表与[硅基官方价格页](https://siliconflow.cn/pricing)均已列出 Qwen3-ASR-1.7B；公开转写文档的模型枚举尚未覆盖该模型，不能把它当作完整可用列表。语音合成模型不能用来识别字幕。点击「刷新模型」后，硅基流动通过 `/models?sub_type=speech-to-text` 或 `/models?sub_type=chat` 分别获取账户可用模型；模型上下线、权限和价格以账户返回和控制台为准。

翻译 Key 留空且两个接口地址同源时，复用识别 Key；不同域名需分别填写。自定义兼容接口使用 `/audio/transcriptions` 和 `/chat/completions`。API 地址填基础地址，不包含完整接口路径。保存设置或刷新模型时会申请对应域名的访问权限。密钥不会出现在视频页面、字幕文件和任务记录中。

## 识别方式

| 档位 | 实际处理 |
| --- | --- |
| 语音短段（默认，同步优先） | 本机解码，按停顿切分，最长 6 秒；每段原始位置直接用于字幕。仅省略完全静音，低音量音频保留 |
| 原音轨整段直传（速度优先） | 直接上传原始压缩音轨；超出单次限制或失败时自动换下一种方式 |
| 分段识别（更稳） | 默认按约 120 秒分段，保留 AAC 原始音频；失败后自动换兼容方式 |
| 兼容识别（较慢） | 本机解码，默认按约 25 秒转换为 WAV 上传 |

语音短段失败时保留已完成片段，重新生成可续传；不会自动降级为整段估算。HTTP 429 / 502 / 503 / 504 最多重试两次，HTTP 401 / 402 / 403 等错误直接报告；429 也可能表示额度不足，仍失败时需检查账户。请求数随视频长度和停顿数量增加，例如本次验证的 18 分钟 P123 音轨为 330 段。已提交的请求如何计费取决于服务商。

其他档位的格式回退复用同一次下载的音轨，已成功片段会保存。Key 无效、欠费、无权限、模型不存在或限流不通过换格式解决，因此直接报告错误；取消不会触发下一次上传。超时、格式不兼容等识别失败会自动尝试后续方式。

硅基流动单请求文档限制为 50 MB / 1 小时，插件按 49 MB 保守阈值判断整段上传。兼容接口按 24 MB 处理。单个视频最长 180 分钟、音轨最大 300 MB；长音轨自动分段。设置页保存后使用统一处理参数，识别请求最多等待 180 秒，翻译每批最多 180 秒。旧版已保存的超时值在重新保存前仍有效。

**识别文字和对齐时间是两件事，不能仅按模型名称判断字幕是否同步。** 硅基公开转写接口目前仅承诺返回 `text`，尚未说明其 Qwen 托管接口的时间戳参数。插件收到有效 `segments: [{start,end,text}]` 时使用接口时间戳。只有文字时，默认语音短段模式将一段识别结果整体显示在它对应的音频窗口内，标记「语音分段时间轴」；其余模式仍按文字长度分配时间，标记「估算时间轴」。

语音短段的起止位置来自原始采样序号，保留中间停顿，不会把静音删除后的时间拼接成另一条时间轴。连续讲话可能被切成多个短段，每段文字会一起出现，仍可能存在段内提前显示或切词问题；需要逐字同步时，仍需真实时间戳或对齐模型。

Qwen 的[官方时间戳方案](https://github.com/QwenLM/Qwen3-ASR#forcedaligner-usage)还需 `Qwen/Qwen3-ForcedAligner-0.6B`，把音频和识别文字一起输入对齐模型；本插件未内置该本地模型，也没有假定硅基提供该接口。更换默认模型不等于已经完成音频对齐。

更新后刷新扩展并刷新视频页，再生成当前 P。模型或模式改变会使用独立缓存，不会把旧的整段估算字幕当作新模式结果；不需要清空其他字幕。原来手动调整过的本集延迟仍保留，核对新字幕时可调回 `0.0 s`。

插件优先下载最低码率独立音轨，下载失败时切换 B 站返回的备用 CDN。不下载视频画面，也不读取 Chrome 磁盘视频缓存。暂不支持直播、番剧、受保护音轨及没有独立 DASH 音轨的视频。

## 常见问题

- **401 / 403**：检查 Key、服务地址与账户模型权限。
- **429**：检查余额或配额，等待后重试。
- **B 站风控 / 下载失败**：登录 B 站，确认视频可播放，等待后重试。
- **翻译失败**：可先使用原文；重试复用已完成识别，不重复上传音轨。
- **模型不在预置列表**：刷新账户模型，或选「自定义模型」填写 ID。
- **自动任务失败后不再重试**：同一会话内避免反复提交；可手动生成，或关闭再开启自动开关。
- **字幕重叠**：在播放器里关闭 B 站原生字幕或插件字幕中的一层。

## 开发与验证

```powershell
npm test
npm run check
npm run build
npm run package
```

`npm run build` 固定更新 `dist/bili-whole-subtitles`，本机路径为 `/Users/ye/code/BiliBiliSubtitle/dist/bili-whole-subtitles`。Chrome 一次加载这个目录后，后续更新不需要重新解压、卸载或选择目录；点扩展卡片的刷新按钮，再刷新 B 站视频页即可。仅刷新视频页不会重新加载已改变的后台脚本或 Manifest。

`npm run package` 先同步上述固定目录，再生成 `dist/bili-whole-subtitles.zip` 和 `.sha256` 校验文件。构建使用 Node.js；打包在 macOS / Linux 使用 `zip`，Windows 使用 PowerShell。运行时依赖的 MP4Box.js 已随包提供，许可见 `src/vendor/LICENSE`。

### 自动发布 Release

将 `manifest.json` 和 `package.json` 的版本号同步更新并提交，然后推送对应标签。例如版本号为 `1.3.1` 时：

```powershell
git push origin main
git tag v1.3.1
git push origin v1.3.1
```

GitHub Actions 自动检查代码、运行测试、生成 `dist/bili-whole-subtitles.zip`，校验标签和安装包版本一致后发布 Release，附带 ZIP 和 SHA-256 校验文件。失败时不会新发布 Release。也可在 Actions 的「Build and release extension」中手动运行，填写已有的版本标签重试。无需配置额外密钥。

`scripts/browser-smoke.mjs` 在隔离浏览器目录中以模拟接口验证：识别、翻译、缓存、自动触发、下一 P、200P 多选、导出、取消、模型刷新及格式回退。通过 `BILI_PLAYWRIGHT_PATH` / `BILI_BROWSER_PATH` 配置测试运行时；`BILI_TEST_AUDIO` 可指向实际 M4A 测试素材。没有使用用户真实 Key 或进行付费请求。

实际用户视频的 704 秒 / 5.65 MiB M4A 音轨已用于本机下载、无损分段与浏览器解码验证。模型识别质量、真实云端耗时和计费需要使用自己的账户确认。详细记录见 [VALIDATION.md](VALIDATION.md) 与 [RESEARCH.md](RESEARCH.md)。

官方参考：[转写接口](https://docs.siliconflow.cn/docs/api/audio-transcriptions-post)、[模型列表](https://docs.siliconflow.cn/docs/api/models-get)、[对话接口](https://docs.siliconflow.cn/docs/api/chat-completions-post)。
